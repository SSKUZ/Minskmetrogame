# План реализации Station Base — ТЗ №1.2

Статус: предложение; выполнение начинается только после отдельного разрешения. Состав v106 и пассажирская ветка закреплены SHA. Каждый этап заканчивается checkpoint и проверкой файлов diff.

| Шаг | Создаваемый модуль | Критерий готовности | Нужны ли изменения существующего поезда/пассажиров |
|---|---|---|---|
| 0 | Версии StationDefinition + TrainCompatibilityProfile | Статусы А/Б/В, единицы, опоры, ID, источник каждого значения; неподдерживаемые комбинации отклоняются | Нет; сначала утверждение проектного профиля |
| 1 | Coordinate/Validation | Прямое/обратное преобразование, первый/последний вагон, контакт 32 колёс; смена пространств 16 дверей без скачка | Нет |
| 2 | Track Module + Tunnel Port Contract | На всём прямом участке одни центры/высоты; два порта на путь, совпадение касательных и рельсовых нитей | Нет; тоннель не строится, старая сцена не исправляется |
| 3 | Platform Module + Clearance | Новый изолированный техстенд, Y=1,1805 и край −1,370 после утверждения; проверка всех треугольников в полосе, закрытые/открытые/движущиеся двери | Нет; используется неизменный поезд и его placement |

## Окончательная структура

- `StationDefinition`: версия, units, frame, provenance, topology, track/platform/exit IDs.
- `TrainCompatibilityProfile`: SHA, rail contact, 32 doors, cars/interior, measured height envelopes.
- `CoordinateAdapter`: canonical → station → world; отдельные adapters Web/Roblox.
- `TrackModule`: рельсовый профиль и ось пути, не декор.
- `PlatformModule`: поверхности, края, тип island/side/split и usable extents.
- `StopModule`: reference, direction, door side, stop tolerance и блокировка обмена.
- `PassengerStationContract`: waiting/spawn/boarding/alighting/exit graph; отдельно от PassengerSystem.
- `TunnelConnector`: типизированные порты и проверка непрерывности; геометрию тоннеля не создаёт.
- `CollisionModule`: физические примитивы, swept clearance и отдельные навигационные препятствия.
- `DecorationInterface`: mounts, уровни и запретные объёмы; отдельный MalinovkaDecoration.
- `Validation`: проверка версий, опор, зазоров, маршрутов, экспорта; результаты как машиночитаемый отчёт.

Общий каркас не фиксирует одну длину, ширину и расстановку колонн для всех станций. Первая реализация может поддерживать только прямой горизонтальный путь; другие топологии остаются в формате, но runtime явно отказывает, пока не реализован соответствующий adapter.

## Что потребует отдельного согласования

1. Применение переноса v106 и нового профиля путей/платформы в основной игре. Текущий checkpoint только вычисляет предлагаемые координаты.
2. Пассажирские изменения: очередь ±0,71, резервирование/семейное соседство сидений, разные passage/swept-door envelopes, реальные выходы, мировые grip frames, поддержка второй стороны/поворотов.
3. Любые изменения исходного train asset, включая колёса, подушки, пороги, двери. Здесь не рекомендуются как скрытая часть Station Base.
4. Реальный профиль колеи, если он не совместим с неизменным v106; до подтверждения использовать только явно названный игровой compatibility profile.
5. Динамика подвески, крен, уклон и кривые; нынешняя проверка не даёт универсального swept envelope для них.
6. Оценённые размеры Малиновки, её временной срез и допустимые отклонения от реального объекта.
7. Roblox-плейс и импортная приёмка. Общие редактируемые DCC/текстуры, геометрия, LOD, коллизии и manifest планируются сразу; JavaScript не является исходным форматом ресурса.

## Приёмка будущего техстенда

Колёса касаются головок при номинальном placement (32/32); боковые координаты совпадают; рельсы совпадают в обоих портах; все 16 дверей нужной стороны попадают в usable extents; нет отрицательного объёмного clearance; закрытие блокируется занятым дверным объёмом. Проверить точный dependency viewer в браузере, а не только CPU-скрипт. Полная динамическая/пассажирская приёмка отдельная и не заменяется снимком остановленного поезда.
