# Station Base v1 — checkpoints

Исходная точка: b0c901161ed97f7964b5921fbdc3f3ace94a498d. Ветка feature/station-base-v1. Все параметры относятся к технической совместимости v106, а не к реальным размерам Малиновки.

## Этап 1. Модульные контракты

Созданы StationDefinition, TrainCompatibilityProfile, TrackModule, PlatformModule, TrainStopModule, TunnelConnector, CollisionModule, PassengerStationContract, DecorationInterface и Validation. Геометрические значения централизованы в data/station-base/v106.js. Выход модулей — данные, независимые от Three.js.

Проверка: node --test tests/station-base.test.js — 6/6. Включены отрицательные сценарии: слишком короткая платформа, неподдерживаемая конфигурация, неправильная высота рельса/двери, несовпадающий порт. Проверено сохранение мировых координат для всех 16 дверей при смене пространства.

Это промежуточный checkpoint: 3D-просмотрщик и проверка фактических mesh ещё не реализованы. Обход колёс должен читать batchedParts, а не исчезающие userData.wheel. Данные пассажиров остаются контрактом, без PassengerSystem. Ни один существующий игровой/поездной файл не изменён.

## Этап 2. Двухпутный просмотрщик и фактические mesh

Создана station-base.html, свободная камера, исходный live v106 через неизменный загрузчик, независимый clone transform graph второго статичного v106, переключатель его видимости. Геометрия и материалы клона разделяют исходные ресурсы; дверные узлы независимы. Центральный профиль: railHead=0, train root +0,220, platform top=1,1805, edge offset=1,370. Ширина демо 8 м: ось второго пути X=−(8+2×1,370)=−10,740 м. Две остановки, 32 привязки по 16 на путь, независимые ожидание/посадка/высадка, четыре TunnelPort. Контракт состояний EMPTY/APPROACHING/STOPPED/BOARDING/DEPARTING; второй поезд в просмотрщике только статичный.

Проверки: 10/10 unit/contract tests; CPU-исполнение исходных построителей на Three r160: 50 положительных сценариев и 4 отрицательных. Обе стороны и направления; 32 колеса на каждом составе, все 16 обслуживаемых проёмов, реальные рельсовые mesh и плита, объёмная полоса, отсутствие пересечений между составами. SHA256 исходных BufferGeometry до/после одинаков. Результаты: test-results/station-base/geometry.json.

Ограничение браузерного QA: cloud Chrome не создаёт WebGL-контекст (GL_VENDOR/GL_RENDERER Disabled). Это не визуальная приёмка; скриншоты успешного 3D пока не получены. Добавлен изолированный CI acceptance workflow с Chromium/SwiftShader, проверкой точного three@0.160.1 и сохранением отчётов/скриншотов только в feature/station-base-v1. Основные deploy workflows и gh-pages не изменены. Пока CI не завершён, рендер не объявляется подтверждённым.

## Этап 3. Браузерная приёмка и диагностика

Первый CI run 41036580296 успешно выполнил contract/CPU tests и получил two-trains-overview.png и platform-gap.png с настоящими mesh, 32/32 колёс и 16/16 дверей. Полный браузерный сценарий не завершился: после этих кадров сработал timeout screenshot; старый catch потерял исходную ошибку. Исправлена сохранность диагностики до попытки failure screenshot, добавлена фиксация пройденных сценариев и более длинный таймаут захвата программным GPU.

Рендер ограничен 20 кадрами/с при движении, без постоянного перерисовывания статичного кадра. Новый материал технической платформы не пересвечивается двумя исходными комплектами света поездов. Метки порогов уменьшены, для обмера можно отключить. Проверяются реальные грани и размеры плиты и рельсов, а не только их параметры. Добавлены корректные occupancy snapshots и обратное направление пересчёта пассажирских координат. Положение основного пути настраивается primaryTrackX; второй вычисляется от него через ширину острова и два edge offsets.

Второй CI run 41037675928 подтвердил открытые двери и блокировку отправления (15/15 текущих mesh checks, pageErrors=[]). Остановился исключительно на захвате doors-open.png; последующий failure screenshot успешно показал тот же открытый поезд. В browser test добавлена одна повторная попытка только для TimeoutError screenshot с сохранением captureWarnings. Геометрические и функциональные ожидания не ослаблены. До полного успешного прогона результат остаётся промежуточным.

Третий CI run 41038588356 повторно подтвердил mesh/открытие дверей без pageErrors, но screenshot открытого кадра не завершился и после повторной попытки. В отдельном техническом renderer включено preserveDrawingBuffer: кадр сохраняется для захвата после остановки перерисовки. Перед фотографированием browser test вызывает штатную кнопку повторного измерения/перерисовки. Это изменение нового просмотрщика, не renderer основной игры и не геометрии v106. Исходные неуспешные runs и отчёты сохранены в истории; приёмка остаётся открытой до успешного полного сценария.

Четвёртый CI run 41039251062 получил кадры doors-open и wheel-rail-contact (с одной повторной попыткой каждый), подтвердил скрытие второго состава. Выявил функциональный дефект демонстрации: ограничение dt одной секундой замедляло 12-секундный подъезд при кадрах SwiftShader дольше секунды; остановка не достигалась за 45 с. Исправлено в viewer: используется фактический монотонный интервал, а при запуске движения/дверей clock сбрасывается на время команды. Основная TrainPhysics не меняется; критерий 45 с не увеличен.

Завершена переносимость ресурсов каркаса: TrackModule экспортирует нейтральные primitive recipes для рельсов, оснований и шпал, PlatformModule — для плиты; отдельно data/station-base/materials.js. StationDefinition содержит platforms[] и platformId у stops, модули — массивы платформ/solids, при этом runtime по-прежнему явно ограничен одним островом. Экспорт JSON включает эти данные и материалы, без Three.js mesh/материалов. Все 12 контрактных проверок и 50 положительных / 6 отрицательных CPU-сценариев на этом представлении пройдены. Добавлен тест крупных интервалов демонстрационного времени.
