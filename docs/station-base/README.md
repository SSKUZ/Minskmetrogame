# Station Base v1 — технический стенд

Два прямых горизонтальных пути, одна островная платформа и два настоящих четырёхвагонных v106. Первый поезд управляется кнопками технического просмотрщика; второй размещён статично у противоположного края и может быть скрыт. Обе стороны и оба направления представлены отдельными остановками и пассажирскими привязками.

Ветка: `feature/station-base-v1`. Исходный checkpoint: `b0c901161ed97f7964b5921fbdc3f3ace94a498d`. Главная страница стенда — `station-base.html`. Это отдельная страница; основная игра и старая «Малиновка» не заменены.

## Геометрия

Единственный runtime-источник числового compatibility profile — `data/station-base/v106.js`.

| Параметр | Значение |
|---|---:|
| Головка рельса | Y=0 |
| Размещение неизменного v106 | Y=+0,220; продольное смещение исходного viewer ±9,603 в зависимости от направления |
| Верх платформы / порога | Y=1,1805 |
| Отступ края от оси пути | 1,370 |
| Две нити каждого игрового пути | Ось пути ±0,900; между центрами 1,800 |
| Зазор до измеренной геометрии на высоте плиты | около 33 мм |
| Зазор до утопленного порога | около 69,5 мм |
| Техническая платформа по умолчанию | 105×8 м, не обмер Малиновки |
| Оси путей по умолчанию | X=0 и X=−10,740 |
| Остановки активной первой кабиной | Z=0 на первом пути; Z=79,224 на встречном |

Формула второго пути: `x2 = x1 − platformWidth − 2*edgeOffset`. Расстояние 10,740 м выведено из выбранной ширины острова и одинаковых зазоров, а не задано произвольно. Размеры 105×8 относится только к демонстрационной конфигурации. Реальная колея и размерный разрез станции этим профилем не подтверждаются.

`direction=-1`: первая кабина движется к −Z, корень train=(trackX;0,220;frontZ+9,603), yaw=0. `direction=+1`: корень=(trackX;0,220;frontZ−9,603), yaw=π. Геометрия вагонов, их исходные локальные преобразования и межвагонные расстояния не редактируются.

У первого пути платформа со стороны мировой −X, у второго +X. Выбор дверей определяется мировой нормалью после применения направления и разворота заднего головного вагона. В станционном контракте каждый путь имеет 16 независимых door IDs, waiting/boarding/alighting zones и свою точку остановки. Четыре TunnelPort задают рамки/касательные/нитки на обоих концах двух путей; геометрии тоннеля нет.

## Реализованные модули

| Модуль | Реализация |
|---|---|
| StationDefinition | Размеры/границы, primaryTrackX, рассчитанный второй путь, две остановки, направления, препятствия и mounts |
| TrainCompatibilityProfile | Централизованные измерения/параметры v106, прямое и обратное преобразование |
| TrackModule | Данные четырёх рельсовых нитей двух путей |
| PlatformModule | Плита и оба края островной платформы |
| TrainStopModule | Отдельные reference/допуски/стороны/16 дверей для каждого пути |
| TunnelConnector | Четыре порта и проверка совмещения нитей с противоположными normals |
| CollisionModule | Тело платформы, препятствия и резервируемые габариты |
| PassengerStationContract | Раздельные зоны двух сторон, ID путей/дверей, преобразование координат в обоих направлениях |
| DecorationInterface | Точки подключения и запретные объёмы; художественное оформление отсутствует |
| Validation + GeometryValidation | Структура/габариты по данным и реальные вершины mesh: колёса, пороги, открытые створки, плита/рельсы и полоса высот |
| TrackOccupancyContract | EMPTY → APPROACHING → STOPPED → BOARDING → DEPARTING → EMPTY, плюс явно обозначенное статичное размещение |
| DemoMotion | Изолированная демонстрационная кинематика, не основная физика игры |
| V106Adapter | Подключение исходного live graph, размещение и обслуживаемые створки; клонирование узлов второго поезда с общими неизменными BufferGeometry/materials |
| WebSceneAdapter | Three.js-представление технических ресурсов; отделено от параметров и логики |

Формат допускает дальнейшие topology, но текущий runtime принимает только `straight-level-island` и явно отклоняет остальные. Пассажирская ветка и PassengerSystem не подключены. Наличие зон не означает работающую посадку людей.

## Управление просмотрщиком

- Свободный осмотр мышью/касанием; отдельные камеры «Общий», «У края», «Колёса», «Сверху».
- «Подъезд» запускает демонстрацию прибытия; «Открыть» доступно только на остановке; «Отправление» блокируется при открытых/движущихся дверях.
- «К остановке» и ↺ — техническая установка на reference, не реалистичное торможение основной игры.
- Переключатель второго v106 управляет его видимостью и статичным состоянием пути; движения, расписания и AI у него нет.
- В параметрах меняются размеры острова и направление первого пути. Встречный поезд разворачивается противоположно. Остановки и второй путь рассчитываются заново.
- «Проверить геометрию» измеряет текущие реальные mesh. JSON содержит подробные контакты/двери обоих поездов и результаты проверок. Экспортирует также нейтральные параметры и модульные контракты.
- Для рассматривания зазора отключите голубые технические метки.

Рендер ограничен 20 кадрами/с во время движения/вращения камеры; статичный кадр постоянно не перерисовывается. Это ограничение стенда, а не результат подтверждённой производительности на планшете. Два v106 содержат около 4,4 млн видимых треугольников в общем ракурсе; слабому устройству может потребоваться скрыть второй состав.

## Автоматическая проверка

```bash
node --test tests/station-base.test.js
node tests/station-base-geometry.mjs . node_modules/three/build/three.module.js
```

Для CPU-проверки нужен Three.js; CI устанавливает точную зависимость исходного viewer `three@0.160.1`. Исследовательский bootstrap выполняет существующие построители в CPU-сцене с заглушкой графического вывода, затем фактический валидатор работает с настоящими вершинами. Он не строит упрощённый заменитель поезда.

50 положительных сценариев: четыре сочетания «путь × направление», по пять door states и семь позиций на прямом пути, плюс проверки двух составов. 32 контакта на каждой проверке, 16 обслуживаемых порогов, четыре реальные рельсовые mesh и фактическая плита. Шесть отрицательных сценариев: сдвиг реального поезда, подъём реального рельса и сдвиг реальной плиты к поезду, для обоих направлений. SHA256 численных BufferGeometry до/после совпадает. Полный отчёт — `test-results/station-base/geometry.json`.

Browser acceptance использует существующий репозиторный Playwright/Chromium в GitHub Actions и отдельно проверяет WebGL-рендер, движения/двери, скрытие второго поезда, обратное направление и экран телефона. Workflow пишет только `test-results/station-base` в текущую feature-ветку; исходные игровые файлы и основной Pages deployment не меняет. Точный результат последнего запуска указан в ACCEPTANCE.md; один CPU-отчёт не заменяет эту проверку.

## Повторное использование и ограничения

Геометрические исходники нового каркаса — редактируемые метрические параметры и модульные primitive descriptors. Материалы/визуальные метки принадлежат Web adapter; габариты и collision descriptors — отдельные данные. JSON экспорт пригоден как исходный контракт для будущего Luau/DCC adapter. Готовый импорт в Roblox, FBX/GLB asset pack и Roblox-плейс не создавались и не заявляются проверенными.

Текущий гарантируемый геометрический режим: прямая, горизонтальная опора, заданные рамки, отсутствие крена/уклона. Зазор проверен отсечением настоящих треугольников по полосе высот; продольное движение не меняет её поперечный экстремум. Пробный боковой бюджет 10 мм оставляет около 23 мм; это collision reserve, не модель подвески.

Отдельно останутся: реальная архитектура/размеры Малиновки; дальнейшие topology; физика подвески и кривых; пассажирская интеграция (сиденья/очереди/поручни/выходы и потребитель второй стороны); движение/расписание/AI встречного поезда; импортная приёмка Roblox; реальные замеры на Honor Pad X9 и телефоне. Исходная реклама и маркировки внутри v106 сохранены как часть существующего ресурса, новое станционное оформление не добавлено.
