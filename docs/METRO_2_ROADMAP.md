# МИНСКОЕ МЕТРО 2.0 — ЕДИНЫЙ ПЛАН РАЗРАБОТКИ
Статус: утверждённые принципы, план исполнения. Версия: 1.0 (31.10.2026).
Плановая ветка: `planning/metro-2-roadmap`. Исходная ветка: `main`.
**Это план, а не подтверждение выполнения этапов.** Отметки DONE допустимы только с доказательствами.

## 0. Неизменяемые принципы
1. **Android-first**: первичный продукт — устанавливаемое Android-приложение (APK/AAB), не браузерная игра в WebView. Движок выбирается после проверки возможностей сборки, профилирования и переноса ассетов.
2. **Low-end-first**: Honor Pad X9 — обязательный физический тестовый планшет с самого первого APK, даже до Station Base. Если физический доступ к устройству отсутствует, тест считается НЕ ПРОЙДЕННЫМ, а не «условно успешным».
3. **Performance-gated**: переход к следующему этапу только после измерений, отчёта и согласования. Не оптимизировать вслепую.
4. **Roblox-ready**: общие спецификации, форматы и переносимые исходники ассетов с первого дня; отдельная реализация Roblox на Luau. Не пытаться использовать один исполняемый код двух движков.
5. **Пассажиры раздельные**: Android — существующие реалистичные пассажиры после аудита; Roblox — новые NPC в стиле Roblox-аватаров. Не переносить реалистичных пассажиров в Roblox.
6. **Сохранность**: не удалять `main`, не менять `testing`, `cab-development`, `integration/consist-v106`, пассажирские и Station Base ветки без отдельного разрешения. Никаких автоматических слияний.
7. **Модульность**: ядро отдельно от станции, поезда, кабины, пассажиров, интерфейса, аудио. Физика и правила не зависят от FPS.
8. **Доказательства вместо обещаний**: каждый пункт закрывается кодом, SHA коммита, APK (когда применимо), измерениями и отчётом.

## 1. Порядок работы между чатами
- Единственный источник последовательности — этот файл `docs/METRO_2_ROADMAP.md` в плановой ветке.
- В начале нового чата: прочитать актуальный план из GitHub, определить последний подтверждённый DONE и текущий IN_PROGRESS; проверить последние коммиты и артефакты.
- Выполнять **один незавершённый пункт за раз**. Не переходить к следующему по собственной инициативе, пока критерии приёмки не выполнены и пользователь не утвердил переход.
- В конце сессии: сохранить результат в отдельной рабочей ветке, сообщить SHA, статус, измерения, блокеры и следующий пункт; обновить план только в плановой ветке.
- Не писать DONE на основании только генерации кода, без проверки.
- Если нет инструментов сборки Android, доступа к планшету или Roblox Studio — явно помечать BLOCKED и описывать нужный способ проверки; не имитировать тестирование.
