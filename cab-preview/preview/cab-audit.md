# Кабина машиниста — этап 1: аудит существующей реализации

Рабочая ветка: `cab-development`. Не изменять `testing` и `main`, пока Work разрабатывает состав.

## Подтверждено по исходникам
- Игровая кабина уже является **трёхмерной сценой**: `js/main.js` создаёт `const cab = new THREE.Group()`, размещает панели, экраны, кнопки, зеркала, окна и стенки.
- Действующая логика анимации кнопок вынесена в `js/cab/CabButtons.js`.
- Дисплей скорости и дверей обновляется через `js/cab/CabDisplay.js`.
- `index.html` также содержит интерфейсные элементы управления и индикации. Их нельзя удалять при визуальной переработке.
- Отдельная 3D-модель вагона в `preview/wagon.html` — другой проектный компонент; **не** использовать её как источник механики кабины.

## План без потери функциональности
1. Зафиксировать текущий внешний вид кабины и список рабочих кнопок/событий.
2. Выделить из `js/main.js` построение `cab` в независимую фабрику `js/cab/CabModel.js`, сохраняя идентификаторы и обработчики.
3. Создать отдельную страницу просмотра `preview/cab-editor.html` с орбитальной камерой и переключателями видимости корпуса; сперва только просмотр, не редактор с сохранением.
4. По фотографиям настоящей кабины 81-717 последовательно уточнить геометрию пульта, приборы, контроллер, окна и отделку.
5. После каждой группы изменений запускать проверки запуска игры, переключения камер, тяги, торможения, дверей, приборов и мобильного отображения.

## Ограничения
- Не переписывать работающую физику и управление.
- Не заменять действующую кабину на нефункциональный макет.
- Не изменять `testing` и `main` без отдельного согласования.
- Для точной геометрии потребуются эталонные фотографии и сверка с ними.
