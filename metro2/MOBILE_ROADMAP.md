# Минское метро 2.0 — мобильный путеводитель разработки
Обновлено: 2026-10-31. Статус: обязательный архитектурный ориентир для ветки `feature/metro2-real-scene-p3-recovery`.

## Цель и принцип
Это **мобильный симулятор машиниста**, а не порт браузерной сцены без оптимизации. Целевые устройства: Samsung Galaxy S24+ и Honor Pad X9. Приоритет: правдоподобие Минского метро, работающие двери и кабина, приемлемые размер загрузки, память и FPS. Каждое расширение должно проходить бюджет ресурсов **до**, а не после интеграции. Изменения оригинальных GLB v106 запрещены: исходники — неизменяемый эталон.

## Составы: один активный, один эпизодический
- **Единственный постоянно симулируемый состав** — поезд игрока (четыре вагона v106).
- Второй путь **не обязан** быть занят. Встречный состав появляется по сценарию/вероятности только на некоторых станциях; может стоять, прибывать, отправляться, открывать двери и обслуживать пассажиров.
- Встречный состав использует **те же общие ресурсы** моделей и материалов, не отдельную копию на каждую станцию. Для него применяются LOD, ограниченная симуляция и упрощённая анимация; нет физики управления машиниста.
- При отсутствии встречного состава не создавать его узлы/меши и не выполнять обновления. Вне видимости — отключать отрисовку и дорогие вычисления.
- Будущая возможность выйти из кабины, пройти по платформе и приблизиться к другому поезду **должна учитываться**: на близкой дистанции доступен качественный LOD, а двери/пассажиры визуально корректны.

## Размер и производительность: бюджеты-гипотезы, уточнить измерениями
- Цель первой загрузки: до **150 МБ**, полной установки со всеми линиями: ориентир до **500 МБ**, не гарантия.
- Целевой FPS: стабильные 30–60 на Honor Pad X9, более высокий — на S24+ при подходящих настройках. Мерить 1% low, память, время загрузки, draw calls, треугольники.
- Базовый v106 (4 GLB): около 122 МБ, 2.17 млн треугольников, 969 мешей (исторические измерения; перепроверить программно и фиксировать версии файлов).
- **Первый целевой бюджет** для мобильного v106: 40–60 МБ на четыре вагона, 500–700 тыс. треугольников, сокращение draw calls/мешей без разрушения отдельных створок и наклеек. Это критерии для эксперимента, не обязательное достижение любой ценой.
- Никаких визуальных компромиссов без сравнения с оригиналом: силуэт, 6 фар головного вагона, кабина, салон, окна, тележки, 64 дверные створки, предупреждающие наклейки и материалы должны сохраниться.
- Отдельно учитывать: размер файлов на диске != RAM/VRAM != число видимых треугольников в кадре; LOD иногда увеличивает размер дистрибутива.

## Архитектура ассетов
1. Хранить `V106 Original` как эталон, отдельно создавать `V106 Mobile`. Никакой замены оригинала «на месте».
2. Начинать с инвентаризации: SHA-256/размеры GLB, число мешей/треугольников, 20 наиболее тяжёлых мешей, размеры и дубликаты текстур, материалы, количество дверей/наклеек.
3. Сначала **без потерь**: устранение дублирующихся данных, повторное использование мешей/материалов, упаковка буферов, удаление заведомо неиспользуемых атрибутов только после проверки, сжатие на диске с проверкой совместимости Godot 4.3. Не обещать снижение числа треугольников без упрощения геометрии.
4. Затем **геометрическая оптимизация** копии: скрытые/мелкие детали, невидимые поверхности, безопасное упрощение, нормали/UV/материалы, отдельные подвижные створки и декали; детальная кабина игрока сохраняется.
5. LOD0 близко, LOD1 средне, LOD2 далеко; отдельный облегчённый LOD для эпизодического встречного состава. Переключение по расстоянию/экранному размеру, проверка при ходьбе по платформе.
6. Станции собирать из общих модулей и уникального оформления; тоннели подгружать участками вокруг поезда; линии — дополнительные пакеты ресурсов по мере необходимости.
7. Держать не больше одной активной сцены станции плюс необходимое окружение; не загружать всю линию одновременно.

## Порядок работ — строго по воротам качества
**Этап A.** Закончить проверку управления Godot 4.3: GDScript, поезд, 3 камеры, 64 створки/наклейки, блокировки. Без сборки APK до PASS.
**Этап B.** Инвентаризация оригинальных четырёх GLB с воспроизводимым отчётом и 20 крупнейшими мешами; подтвердить исходные SHA.
**Этап C.** Создать и измерить первую безопасную оптимизированную копию `V106 Mobile`; провести автоматическую проверку GLB, мешей/дверей/наклеек/материалов.
**Этап D.** Визуальный регрессионный тест оригинал vs Mobile (кабина, боковины, салон, двери, тележки), проверка на Godot/Android; откат при заметном ухудшении.
**Этап E.** Встроить Mobile только после PASS, измерить APK, FPS, RAM, draw calls; не расширять контент до соблюдения базового бюджета.
**Этап F.** Модульные станции, подгрузка тоннелей и эпизодический встречный поезд; затем пассажиры и выход игрока на платформу.

## Правила разработки
- Изменять только recovery-ветку; не сливать в `main`, `testing` или Three.js ветки без отдельного решения.
- Любой отчёт разделяет: **измерено / реализовано / проверено в Godot / проверено на Android**.
- Не делать очередную APK без проверки кода; не начинать новые станции, пока не выполнены базовые бюджеты и тесты.
- Если оптимизация требует ухудшения внешнего вида — остановиться и предложить альтернативу с конкретными метриками.
