# Кабина 81-717: контроль переноса cab-r2 в Godot 4.3

Источник: ветка `cab-development`, `js/cab/CabModel.js`, `CabShell.js`, `CabDesk.js`, `CabEquipment.js`, `CabControls.js`, `CabInstruments.js`.

## Проверенные факты по исходникам
- Кабина генерируется программно в Three.js, готового GLB в исходном коде не обнаружено.
- Локальная геометрия кабины задаётся в метрах; `root.scale.setScalar(1.65)` и `root.position.set(0,.65,.35)` — преобразования для **старой браузерной игры**, НЕ переносить их в GLB.
- Лобовая стенка находится около локального Z=0.38; задняя перегородка около Z=3.55; локальный +Z направлен назад в салон.
- Атлас надписей рисуется на canvas; PBR-поверхности генерируются программно; экспорт требует корректного запекания/сохранения текстур.
- Динамические зеркала, видеомонитор, Three.js SpotLight, raycast и обработчики управления не становятся функциональными после экспорта GLB.
- Неподвижные детали могут быть объединены, но подвижные рычаги/кнопки/дворники должны оставаться отдельными именованными узлами.

## Минимальный эксперимент — не пересоздавать кабину
1. В среде с доступом к ветке `cab-development` вызвать существующий `createCabModel(THREE,renderer)`; получить `model.root`.
2. Экспортировать **геометрию и текстуры** через `GLTFExporter` без изменения геометрии. Перед экспортом сбросить legacy root scale/position; убрать свет, камеры и WebGLRenderTarget-зависимые поверхности; сохранять отдельные подвижные узлы.
3. Сохранить `metro2/assets/cab/cab_81_717.glb` **только в ветку `feature/metro2-first-playable`**; при ограничениях GitHub API использовать проверенное разбиение на части + манифест и скрипт восстановления. Не изменять `cab-development`.
4. Проверить размер, SHA-256 и импорт GLB в Godot. Не считать экспорт успешным, пока модель не открывается и не видны приборы/надписи.
5. Проверить посадку модели внутри головного вагона v106, отсутствие двойной оболочки, отсутствие перекрытия окон и положение камеры машиниста. Текущая точка крепления и камера — **черновые**, не утверждённые координаты.
6. Только после визуальной проверки подключать команды и анимацию на GDScript.

## Критерий решения
Если один минимальный экспорт даёт корректную геометрию и текстуры — используем гибрид. Если экспорт требует существенной переработки атласа, материалов или структуры узлов — останавливаем конвертацию и создаём Godot-native кабину по исходным размерам и эталонным изображениям. Не выполнять бесконечные повторные попытки.

## Ограничения
Не собирать APK до проверки реального GLB. Не подменять отсутствующий GLB упрощённым макетом. Не считать неподтверждённый экспорт выполненным. Минимизировать Work: только экспорт, сохранение и одна проверка импорта; никакой оптимизации, новых моделей и косметических правок.
