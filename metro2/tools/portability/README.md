# Переносимые модули — основа ТЗ №53.1

Это отдельные офлайн-контракты для будущего экспортёра. Они не подключены к игре, автозагрузке, каталогу, просмотрщику или CI упаковки. Нет экспорта, запуска генераторов, записи GLB, обхода всех модулей или преобразования в Roblox. Существующие станции и модели не требуют изменений.

## Файлы и точки входа

- `portable_module.schema.json` — JSON Schema 2020-12, формат метаданных версии 1.
- `portable_module.gd` — фабрика черновика из существующего `modules/core/module_catalog.gd`, сериализация локальных трансформаций и явная регистрация адаптеров.
- `scene_adapter.gd` — интерфейс и базовый читающий адаптер: получает Mesh, MultiMesh, материалы поверхностей, Marker3D, AnimationPlayer и Skeleton3D уже инициализированного модуля. Не создаёт и не меняет узлы/ресурсы.

Будущий модуль может хранить `portable_module.json` рядом со своей сценой. Это необязательное дополнение: отсутствие файла у исторической станции не ломает её загрузку. Для новых модулей с данными вне существующего каталога (например, отдельная кабина) заполняется тот же контракт с явным ID, типом и источником; второй реестр не нужен.

Пример использования **в будущем офлайн-инструменте**, а не команда запуска:

```gdscript
const Metadata = preload("res://tools/portability/portable_module.gd")
const SceneAdapter = preload("res://tools/portability/scene_adapter.gd")

var descriptor: Dictionary = Metadata.draft_from_catalog("moskovskaya")
# Черновик содержит только путь сцены; она не загружается и не создаётся.
# Дополнить источники, материалы, точки, зоны и реальные данные модуля.
var metadata_json: String = JSON.stringify(descriptor, "  ")

var adapters := Metadata.new()
adapters.register_adapter(SceneAdapter.new())
# Уже имеющийся initialized_root предоставляется вызывающим инструментом явно.
# var adapter: RefCounted = adapters.adapter_for(descriptor)
# var handles: Dictionary = adapter.inspect(initialized_root)
```

Специализированный адаптер наследует `scene_adapter.gd`, задаёт уникальный `adapter_id()`, уточняет `accepts(descriptor)` и переопределяет `inspect(root)`. Последний зарегистрированный подходящий адаптер имеет приоритет. Подсказки `adapter_hints` — данные: JSON не загружает и не исполняет скрипты автоматически. При несовместимой версии `adapter_for` возвращает null.

`inspect` возвращает **живые ссылки Godot**, а не JSON: `geometry` содержит Mesh/ArrayMesh/PrimitiveMesh, исходный MultiMesh и трансформацию относительно корня. Для MeshInstance3D учитывается активный материал каждой поверхности, включая override. Для MultiMesh сохраняется ресурс с трансформациями, цветами и custom data; экземпляры не разворачиваются в тысячи новых узлов. Учитываются видимость и visible_instance_count; скрытые экземпляры не следует безусловно экспортировать. `animation_handles` и `skeleton_handles` сохраняют ссылки на проигрыватель и скелет. ТЗ №53.2 должно преобразовать эти ресурсы в glTF и сериализуемые метаданные, не менять оригиналы.

Поле `points` из адаптера содержит Marker3D с ролью `custom`. Имена не доказывают назначение: автор модуля или специализированный адаптер явно указывает connection, door, bogie, cab, controller, brake, camera, stop, spawn, boarding, alighting, waiting, seat, grip, interaction и equipment. `zones` поддерживает локальные box/sphere/capsule/polygon. Нераспознанные семантика и зоны не выдумываются.

## Координаты, материалы и данные

Источник: текущие метры из Catalog.METRES_PER_UNIT, правая система, +Y вверх, стандартный forward −Z. Ось маршрута +Z; движение к Уручью −Z. Начало координат — корень конкретного модуля. Значения transform включают масштаб; это 16 чисел по столбцам, перенос в элементах 12–14, кватернионы при добавлении — x/y/z/w. Матрицы точек и зон относятся к корню, не к родителю маркера. Путь skeleton_path в живом handle сохраняет исходную интерпретацию Godot относительно MeshInstance3D.

`target_frame.studs_per_metre` и `basis_from_source` изначально null. Это намеренно не выбранные параметры. Будущий экспортёр должен потребовать явное соглашение перед преобразованием. Basis — 9 безразмерных чисел по столбцам; преобразование единиц задаётся отдельно. Нельзя дважды применить масштаб, потерять non-uniform scale или изменить текущие размеры ради Roblox.

`geometry_sources` описывает scene/generator/GLB/glTF/mesh_resource/multipart_glb, параметры и при необходимости привязки материалов к поверхностям. Для процедурной станции указываются скрипт генератора и источник параметров; доступ к мешам обеспечивается после штатного создания одним вызывающим инструментом. Состояние `unassessed` означает отсутствие подтверждения экспортируемости; фабрика не анализирует содержимое сцены.

`materials` и `textures` сохраняют ссылки на исходники, албедо, metallic, roughness, emission, alpha, UV и при необходимости исходник/параметры шейдера. Это данные, не автоматическое сопоставление с Roblox SurfaceAppearance. Идентификаторы ссылок должны быть уникальны в модуле; существование файлов и перекрёстные ссылки проверит будущий экспортёр. Схема определяет форму, не подтверждает семантическую корректность.

`data.parameters` — значения с единицами и источником (ускорение, торможение, ограничения скорости, параметры дверей и камер). `data.references` позволяет сослаться на существующий JSON сидений/посадки, не копируя его. `routes`, `equipment_states`, `animations` описывают пути, состояния и параметры клипов. Они не содержат и не исполняют ИИ или контроллер. Поддерживаются ссылки на исходный скелет и будущий R15, но ретаргетинг остаётся `unassessed`/`required`.

## Конкретные границы для ТЗ №53.2

| Объект | Что сохраняет основа | Что ещё потребуется |
| --- | --- | --- |
| Уручье, Борисовский тракт, Восток, Московская, Парк Челюскинцев и другие процедурные станции | Путь из каталога; доступ к Mesh/ArrayMesh и MultiMesh после инициализации | Контролируемое создание одной сцены, преобразование PrimitiveMesh/поверхностей и экземпляров в glTF, выбор LOD/видимости и извлечение исходных параметров |
| GDScript-шейдеры камня, дерева, балласта, освещения | Живой ShaderMaterial и его параметры; явное ограничение `godot_shader` | Подходящее PBR-представление, UV/трипланарное запекание; автоматическая переносимость не обещается |
| Зеркала и CCTV на SubViewport | Ограничение `viewport_texture` для native-материалов | Отдельная реализация отражения/камеры в Roblox; материал ShaderMaterial с динамической текстурой требует специализированного анализа |
| Геометрия без MeshInstance3D/MultiMeshInstance3D, например CSG/частицы/Label3D | Ограничение `non_mesh_geometry`, если узел является GeometryInstance3D | Извлечение/конвертация конкретного типа; декали, свет, коллизии и навигация общим адаптером не конвертируются |
| V106 и кабина, сохранённые GLB/частями | Формат источника multipart_glb/GLB, функциональные точки, skin/skeleton/blend-shape handles | Восстановление существующими средствами при будущей работе, сохранение иерархии и динамических дверей; skin/blend shapes требуют специального адаптера |
| Пассажиры и анимации | Ссылки на данные маршрутов/сидений, маркеры и именованные клипы | Сопоставление скелета R15, перенос поведения на Luau; процедурные GDScript-позы сами не становятся клипами |

Список — границы контракта и уже видимых архитектурных типов, не полный аудит станций и не результат проверок. Существующие модули не преобразованы и не объявлены гарантированно импортируемыми. Экспорт glTF/GLB, перенос света/физики/камер, bake материалов, поведение и R15 относятся к будущему ТЗ №53.2.

Файлы расположены вне runtime-каталогов. Текущий workflow отслеживает `tools/automated_deploy`, но не `tools/portability`: эта подготовка не запускает дополнительные веб-сборки и не меняет опубликованные пакеты. Для будущего использования сначала включить эту ветку в согласованный источник новой разработки; другие рабочие ветки не получают файлы и правила автоматически. Автоматических слияний не предусмотрено.
