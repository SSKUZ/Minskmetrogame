# Этап 3 — без потери качества: точная сварка повторных вершин
Дата: 2026-10-31. **Прототип, не интегрирован в Godot.**

Использованы оригинальные четыре GLB. В крупных статических мешах найдены повторяющиеся вершины с одинаковым набором атрибутов POSITION/NORMAL/TEXCOORD_0. Алгоритм объединяет **только побайтно совпадающие полные вершины** и пересчитывает индексы треугольников. UV-швы, нормали, материалы, исходные позиции, двери и наклейки не меняются.

|---|---:|---:|---:|
|01|32 324 584|24 254 600|8 069 984|
|02|28 658 552|20 865 556|7 792 996|
|03|28 658 552|20 865 556|7 792 996|
|04|32 305 384|24 239 540|8 065 844|
|**Всего**|**121 947 072**|**90 225 232**|**31 721 840 (26.01%)**|

**Доказанная проверка:** для каждого индексированного треугольника каждого меша проверено побайтное совпадение атрибутов каждой из трёх вершин между исходным и оптимизированным GLB. Число мешей/узлов/материалов не менялось. Число треугольников **2 167 962 — не изменилось**. Уменьшена только избыточная память вершин и размер файлов. Внешний вид/блеск намеренно не менялся.

**Ограничения:** не выполнен импорт в Godot 4.3, проверка анимации дверей и Android. Данные оригинальных PNG не редактировались. Измерения размера APK, VRAM, draw calls и FPS отсутствуют. Для визуального релиза обязателен тест. Результаты локально упакованы в `v106_mobile_exact_weld_v3.zip`; бинарники **не загружены в GitHub**.

**Рекомендация:** сначала проверить v3 в Godot и сравнить рендер с оригиналом; только затем переходить к снижению количества треугольников, иначе есть риск разрушить крупные статические батчи.
