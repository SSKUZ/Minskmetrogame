# Решения, правила и открытые вопросы

## Принятые принципы
- Разделять поезд, кабину, пассажиров, станции и интеграцию по рабочим веткам.
- Регулярно фиксировать промежуточные результаты в GitHub и сообщать SHA.
- Не сливать ветки и не заменять стабильную сцену без согласования и приёмки.
- Новые 3D-ресурсы проектировать для повторного использования в веб-игре и Roblox; форматы GLB/glTF и редактируемые исходники, где применимо.
- Station Base — **параметризуемая архитектура**, не одна неизменная платформа для всех станций.
- Сохранять оригинальную геометрию v106 при проектировании станций; решать несовпадение координат профилем размещения, если это технически возможно.
- Сначала геометрия и тестовая сцена, затем интеграция пассажиров, затем реалистичная отделка станции.
- Старая условная «Малиновка» не удаляется до успешной приёмки новой.
- Не путать прохождение unit/CPU-проверок, браузерный рендер и реальный FPS на Android.

## Неутверждённые параметры
- RailHead datum и итоговый TrackProfile, реальная колея и размещение колёс.
- Вертикальное положение платформы и целевые зазоры до кузова/порога.
- Подтверждённые размеры построенной «Малиновки» и расположение обоих торцов/лестниц.
- Точные seat/grip/door anchors для интеграции пассажиров в v106.
- Итоговая производительность на реальных мобильных устройствах.

## Требуют отдельного разрешения
- Создание 3D Station Base и подключение к основному runtime.
- Изменения поезда v106, пассажиров, кабины.
- Замена старой станции, интеграция рабочих веток, публикация/релиз.
