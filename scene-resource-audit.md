## Статический аудит исходников

1. Станция: `WebSceneAdapter.js` использует InstancedMesh для шпал и маркеров остановки; основные поверхности представлены простыми BoxGeometry. Это снижает вероятность того, что станция сама по себе создаёт тысячи draw calls, но численный вклад требует живого замера.
2. Второй поезд: `cloneV106Consist` клонирует дерево объектов, сохраняя ссылки на неизменяемые геометрии и материалы. Повторное использование ресурсов уже предусмотрено.
3. Дальний поезд: `OpposingTrainProxyLOD.js` объединяет части прокси по материалу и вагону, сокращая вызовы отрисовки.
4. Рендер: `viewer.js` вызывает `renderer.render` четыре раза за обновление кадра (слои 0, 2, 1, 3). Суммарные draw calls включают проходы всех этих слоёв. Сокращать проходы без проверки слоёв и освещения v106 опасно.
5. FPS: цикл перерисовывает сцену только при `dirty`, с ограничением 20 FPS. Счётчик `FPS(render)` не равен частоте анимационного цикла и не является замером реального мобильного FPS.
6. `GraphicsPresets.js`: low задаёт DPR 0.85 и более ранний переход на LOD; размеры текстур и GPU-память не измерены.

## Добавленный инструмент

`js/station-base/SceneResourceAudit.js` собирает **по отдельности** для станции, игрового и встречного составов: количество объектов, мешей, InstancedMesh/экземпляров, исходных треугольников, материалов, уникальных геометрий и текстур, слоты слоёв, ориентировочный объём геометрических буферов и текстур. Общие ресурсы учитываются уникально.

После загрузки обоих составов результат доступен в консоли браузера как `window.metroSceneResourceAudit`.

### Ограничения

Инвентаризация CPU не является измерением реальных draw calls по компонентам: они зависят от видимости, материалов, групп геометрии, frustum culling и нескольких проходов рендера. Текстурная память — грубая оценка без учёта сжатия, mipmaps и драйвера.

**В текущей сессии нет доступного браузерного GPU-раннера для исполнения сцены. Поэтому фактические численные разбивки по компонентам ещё не получены.** Нельзя выдавать статические оценки за измерения.

## Предварительные приоритеты оптимизации

1. Получить снимок `metroSceneResourceAudit` из запуска сцены.
2. Замерить draw calls отдельно для слоёв/проходов (с сохранением внешнего вида).
3. Выявить детали поездов с наибольшим числом мешей и материал-слотов.
4. Оценить фактическую видеопамять на устройстве, когда появится доступ.

## Контроль изменений

Только два файла: новый модуль аудита и подключение к просмотрщику. Исходная геометрия, механика поездов, LOD-пороги, режимы рендера не изменялись. Нет слияний в другие ветки.
